# v2.9.0 架构升级实施计划

> **目标**: 事件总线 + BullMQ 队列 + Meilisearch 搜索 + Redis 缓存 + Prisma 索引优化
> **基线**: v2.8.0 (通知中心 + Markdown 编辑器 + 性能优化 + E2E 测试)
> **验收标准**: 前后端构建零警告、E2E 9/9 通过、单元测试 113/113 通过

---

## Phase 1: 基础依赖与 Prisma 索引

### 1.1 安装依赖
```bash
cd talentpro-backend
npm install @nestjs/event-emitter
```

### 1.2 Prisma Schema 索引补全
在 `prisma/schema.prisma` 中添加缺失索引：
- `ForumPost`: `topicId`, `authorId`
- `ForumTopic`: `categoryId`, `authorId`
- `BlogPost`: `authorId`, `categoryId`
- `Product`: `tabId`, `isPublished`
- `Resource`: `categoryId`, `status`
- `RefreshToken`: `userId`

### 1.3 Prisma Migrate
```bash
npx prisma migrate dev --name v2_9_0_indexes
```

## Phase 2: Redis + BullMQ + EventEmitter 基础设施

### 2.1 Redis 配置模块
新建 `talentpro-backend/apps/api/src/modules/redis/redis.module.ts`
- 导出 `Redis` 客户端 (ioredis)
- 从 `REDIS_URL` 环境变量读取

### 2.2 BullMQ 注册
修改 `app.module.ts`:
- 导入 `BullModule.forRoot({ connection: redisConfig })`

### 2.3 EventEmitter 注册
修改 `app.module.ts`:
- 导入 `EventEmitterModule.forRoot({ wildcard: true })`

### 2.4 队列定义
新建 `talentpro-backend/apps/api/src/modules/queue/queue.module.ts`
- 注册队列: `notification`, `search-index`
- 导出 `BullModule`

---

## Phase 3: 事件驱动架构

### 3.1 事件定义
新建 `talentpro-backend/apps/api/src/events/`
- `comment-created.event.ts` - payload: comment, author, entityType, entityId
- `notification.event.ts` - payload: userId, type, title, content, data
- `search-index.event.ts` - payload: entityType, entityId, action('create'|'update'|'delete')

### 3.2 事件发布
修改 `blog.service.ts` / `forum.service.ts`:
- 评论/回复创建后，emit `CommentCreatedEvent`
- 不再直接调用 notificationService.create()

### 3.3 事件监听
新建 `talentpro-backend/apps/api/src/listeners/`
- `notification.listener.ts` - 监听 CommentCreatedEvent → 发布 NotificationEvent
- `search-index.listener.ts` - 监听 CommentCreatedEvent / BlogPost changes → 发布 SearchIndexEvent

---

## Phase 4: BullMQ 异步处理器

### 4.1 Notification Processor
新建 `talentpro-backend/apps/api/src/processors/notification.processor.ts`
- 消费 `notification` 队列
- 调用 Prisma 创建 Notification 记录
- 触发 SSE 推送

### 4.2 Search Index Processor
新建 `talentpro-backend/apps/api/src/processors/search-index.processor.ts`
- 消费 `search-index` 队列
- 调用 Meilisearch 索引操作

---

## Phase 5: Meilisearch 搜索重构

### 5.1 Meilisearch 客户端模块
新建 `talentpro-backend/apps/api/src/modules/meilisearch/meilisearch.module.ts`
- 使用 `meilisearch` npm 包
- 配置 host/apiKey 从环境变量

### 5.2 SearchService 重构
重写 `search.service.ts`:
- 初始化时创建 Meilisearch indexes: `blog_posts`, `forum_topics`, `products`
- 设置中文分词 (Meilisearch 内置中文支持)
- `search()` 方法改为调用 Meilisearch
- `addDocuments()` / `updateDocuments()` / `deleteDocuments()` 用于索引维护

### 5.3 初始索引
在应用启动时，将现有数据批量导入 Meilisearch

---

## Phase 6: Redis 缓存层

### 6.1 Cache 拦截器 / 装饰器
新建 `talentpro-backend/apps/api/src/common/decorators/cache.decorator.ts`
- `@CacheKey(key, ttl)` 装饰器

### 6.2 Cache 拦截器
新建 `talentpro-backend/apps/api/src/common/interceptors/cache.interceptor.ts`
- 基于 Redis 的 GET/SET
- 缓存热点接口: CMS 数据、首页内容、博客列表

### 6.3 缓存失效
在 Blog/Forum 内容变更时，清除对应缓存

---

## Phase 7: 可观测性 + 限流

### 7.1 API 响应时间监控
新建 `talentpro-backend/apps/api/src/common/interceptors/timing.interceptor.ts`
- 记录每个请求的处理时间
- 慢请求 (>500ms) 输出 warn log

### 7.2 限流细化
修改 `app.module.ts` ThrottlerModule:
- 公共接口: 100 req/min
- 登录/注册: 10 req/min
- 搜索: 30 req/min
